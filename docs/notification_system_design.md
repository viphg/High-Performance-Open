# 通知提醒系统设计方案

## 📋 项目概述

为High-Performance个人成长管理平台设计并实现一个完整的通知提醒系统，包括站内信、邮件通知、定时任务调度等功能，帮助用户及时获取任务到期、目标进度、成就解锁等重要信息。

## 🗄️ 数据模型

### 1. 通知记录表 (notifications)

存储所有通知记录，包括站内信、邮件发送状态等。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer | 主键 |
| user_id | Integer | 接收用户ID |
| type | String(50) | 通知类型 |
| title | String(200) | 通知标题 |
| content | Text | 通知内容 |
| related_type | String(50) | 关联对象类型 |
| related_id | Integer | 关联对象ID |
| is_read | Boolean | 是否已读 |
| read_at | DateTime | 阅读时间 |
| channel | String(20) | 发送渠道 |
| email_sent | Boolean | 邮件已发送 |
| created_at | DateTime | 创建时间 |

### 2. 通知偏好表 (notification_preferences)

存储用户个性化的通知设置。

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | Integer | 用户ID |
| task_due_email | Boolean | 任务到期邮件 |
| task_due_web | Boolean | 任务到期站内 |
| task_due_hours_before | Integer | 提前提醒小时数 |
| goal_progress_email | Boolean | 目标进度邮件 |
| goal_progress_web | Boolean | 目标进度站内 |
| daily_digest | Boolean | 每日摘要 |
| digest_time | Time | 摘要发送时间 |

## 🔔 通知类型

### 任务相关

1. **TASK_DUE_SOON** - 任务即将到期
   - 触发：任务到期前24小时（可配置）
   - 渠道：站内信 + 邮件
   - 模板：「⏰ 任务【{title}】将在{hours}小时后到期」

2. **TASK_OVERDUE** - 任务已逾期
   - 触发：任务已逾期
   - 渠道：站内信 + 邮件
   - 模板：「⚠️ 任务【{title}】已逾期{days}天」

3. **TASK_COMPLETED** - 任务完成
   - 触发：用户标记任务完成
   - 渠道：站内信
   - 模板：「✅ 恭喜！您已完成任务【{title}】」

### 目标相关

4. **GOAL_PROGRESS** - 目标进度更新
   - 触发：进度达到25%、50%、75%、100%
   - 渠道：站内信
   - 模板：「📈 目标【{title}】进度已达{progress}%」

5. **GOAL_COMPLETED** - 目标达成
   - 触发：目标100%完成
   - 渠道：站内信 + 邮件
   - 模板：「🎉 太棒了！您已完成目标【{title}】」

6. **GOAL_DUE_SOON** - 目标即将到期
   - 触发：目标截止日期前7天
   - 渠道：站内信 + 邮件
   - 模板：「📅 目标【{title}】将在{days}天后到期」

### 成就相关

7. **ACHIEVEMENT_UNLOCKED** - 成就解锁
   - 触发：解锁新成就
   - 渠道：站内信 + 邮件
   - 模板：「🏆 恭喜解锁成就【{title}】」

8. **STREAK_MILESTONE** - 连续打卡里程碑
   - 触发：连续打卡3、7、14、30、60、90、180、365天
   - 渠道：站内信
   - 模板：「🔥 连续打卡{days}天！」

### 系统相关

9. **WELCOME** - 欢迎新用户
   - 触发：用户注册
   - 渠道：站内信 + 邮件
   - 模板：欢迎邮件内容

10. **DAILY_DIGEST** - 每日摘要
    - 触发：每天早上8点（可配置）
    - 渠道：邮件 + 站内信
    - 内容：今日待办任务统计

11. **SYSTEM_ANNOUNCEMENT** - 系统公告
    - 触发：管理员发布
    - 渠道：站内信 + 邮件

## ⚙️ 定时任务调度

### 调度器配置

使用 **APScheduler** 实现后台定时任务：

```python
# 任务调度配置
┌────────────────────────┬───────────────┬────────────────┐
│ 任务名称               │ 执行频率      │ 说明           │
├────────────────────────┼───────────────┼────────────────┤
│ check_due_tasks        │ 每30分钟      │ 检查即将到期   │
│ check_overdue_tasks    │ 每60分钟      │ 检查逾期任务   │
│ check_due_goals        │ 每天9:00      │ 检查即将到期   │
│ send_daily_digests     │ 每天8:00      │ 发送每日摘要   │
└────────────────────────┴───────────────┴────────────────┘
```

### 任务详情

1. **check_due_tasks** (每30分钟)
   - 扫描所有未完成任务
   - 检查是否到达提醒时间
   - 避免24小时内重复发送

2. **check_overdue_tasks** (每60分钟)
   - 扫描所有已逾期任务
   - 发送逾期提醒
   - 避免24小时内重复发送

3. **check_due_goals** (每天9:00)
   - 扫描7天内到期的目标
   - 发送到期提醒
   - 避免7天内重复发送

4. **send_daily_digests** (每天8:00)
   - 生成用户任务统计
   - 发送邮件和站内信
   - 根据用户设置的时间

## 🔌 API 端点

### 通知管理 API

```
GET    /api/v1/notifications           # 获取通知列表
GET    /api/v1/notifications/count     # 获取未读数量
POST   /api/v1/notifications/{id}/read # 标记已读
POST   /api/v1/notifications/read-all  # 全部已读
DELETE /api/v1/notifications/{id}      # 删除通知
```

### 通知偏好 API

```
GET    /api/v1/notifications/preferences           # 获取偏好设置
PUT    /api/v1/notifications/preferences           # 更新偏好设置
```

## 🎨 前端界面

### 组件列表

1. **NotificationBell** - 通知铃铛组件
   - 显示未读数量徽章
   - 下拉通知列表
   - 实时刷新（30秒间隔）

2. **NotificationsPage** - 通知中心页面
   - 全部/未读标签页
   - 通知列表展示
   - 批量操作（全部已读）

3. **NotificationSettings** - 通知设置页面
   - 开关控制各项通知
   - 时间选择器
   - 保存设置

### 用户交互流程

```
用户创建任务
    ↓
系统保存任务
    ↓
触发任务创建事件
    ↓
通知服务创建到期提醒（延迟任务）
    ↓
定时任务检查到期时间
    ↓
发送站内信 + 邮件（根据用户偏好）
    ↓
前端通知铃铛显示未读数
    ↓
用户点击铃铛查看通知
    ↓
用户点击通知跳转到任务详情
```

## 📊 性能考虑

### 数据库优化

1. **索引设计**
   - notifications.user_id (索引)
   - notifications.is_read (索引)
   - notifications.type (索引)
   - notifications.created_at (索引)

2. **数据清理**
   - 定期清理已读通知（30天后）
   - 保留重要通知（系统公告）

### 邮件发送优化

1. **异步发送**
   - 使用Celery队列
   - 避免阻塞主线程

2. **批量发送**
   - 每日摘要合并发送
   - 避免频繁单发

3. **限流控制**
   - 单用户每小时最多10封邮件
   - 防止邮件轰炸

## 🔒 安全考虑

1. **用户隔离**
   - 只能查看自己的通知
   - 只能修改自己的偏好设置

2. **内容安全**
   - 邮件内容转义处理
   - 防止XSS攻击

3. **频率限制**
   - API调用频率限制
   - 防止滥用

4. **隐私保护**
   - 不发送敏感信息到邮件
   - 邮件链接需要登录
